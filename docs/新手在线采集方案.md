# 新手在线采集与自动建模方案

状态：0.3 已实现采集向导、仿真演示、USB 串口数值 CSV、增量文件跟随、通道模板与完整采样/预测记录。下面保留设计依据；实际操作和当前限制见 `../README.md`。真实 USB 硬件尚待用户设备联调，网络与厂商 SDK 接入仍属后续范围。

## 1. 用户目标与默认流程

用户完成三步：**选择设备 → 连接并查看数据 → 开始自动建模**。普通操作界面不要求输入会话 ID、URL、算法名、矩阵或模型阶次，也不要求运行 Python 脚本。

默认任务是建立“输入信号到输出响应”的动态模型，采用现有 ARX 自动定阶与 RLS 跟踪。具有物理含义的参数辨识需要对应设备/物理模型模板，不能把通用 ARX 系数直接标注为电阻、惯量等物理参数。

## 2. 三步向导

| 步骤 | 用户操作 | 软件完成的工作 |
| --- | --- | --- |
| 选择设备 | 选择“USB 采集设备”，从列表选择设备与已配置模板 | 枚举设备，载入通信参数、报文格式、通道含义和单位；记住上次配置 |
| 连接并预览 | 点击“连接设备”，核对页面上的输入/输出名称及实时数值 | 接收原始采样，显示两条实时曲线、时间信息和接收状态；检查格式、时间连续性与缺失数据 |
| 自动建模 | 接收正常后点击“开始自动建模” | 自动创建内部会话、缓冲样本、搜索阶次和延迟、递推更新参数、绘图并记录数据 |

设备模板若预先配置完成，第二次使用只需“连接设备 → 开始自动建模”。为避免误识别，首次通道含义仍需核对；软件不能凭数值自动确定物理量。

## 3. 主页面只呈现操作所需信息

主界面依次显示：

1. **设备连接卡**：设备名称、模板名称、连接/断开按钮。
2. **采样预览卡**：输入/输出的中文名称、单位、最新值和曲线；例如“输入：实际电压 / V；输出：转速 / rad/s”。
3. **建模进度卡**：未连接、等待数据、接收正常、正在收集初始样本、正在自动选阶、正在更新模型、已结束。
4. **结果卡**：推荐阶次、模型响应与测量对比、当前预测误差、已接收样本数、保存结果按钮。

采样周期、波特率、通道映射、模型结构、遗忘因子等置于可折叠的“高级设置”。默认从设备模板读取。HTTP 会话接口保留给开发者使用，不出现在新手主流程中。

无硬件时提供“一键体验演示”按钮，自动产生明确标注为仿真的数据，以同一流程演示接收、自动定阶和模型更新。

## 4. 数据接入优先级

| 来源 | 对普通用户的操作 | 实施要求 |
| --- | --- | --- |
| USB 串口设备 | 插入设备，选择设备名称，点击连接 | 已安装 pyserial 3.5；支持数值 CSV 行协议，首次核对通信参数和通道后保存模板 |
| 持续更新的 CSV | 选择采集软件正在追加的文件，点击跟随采集 | 增量读取完整新行，识别文件截断/重新创建，不反复导入整个文件；需允许并发读取 |
| 网口/厂商采集卡 | 选择已配置的设备模板，点击连接 | 按实际 UDP/TCP/厂商 SDK 开发适配器，不能只凭“网口”判断数据协议 |
| 仿真演示 | 点击一键体验 | 无硬件依赖，必须明确标注模拟数据 |

建议优先实现实际设备所用的一个接口和一键演示，再增加其他接口。若当前采集软件已经稳定输出 CSV，文件跟随模式通常能减少首次设备适配工作。

## 5. 一次性设备模板

模板由开发者或设备提供者配置一次，普通用户选择模板即可。最小信息包括：

- 设备名称及连接方式；串口模板包含实际波特率、数据位、校验与停止位。
- 数据帧格式、分隔符、校验方式，以及如何识别完整的一帧。
- 设备时间戳的字段与单位；没有时间戳时，需要设备提供可信的固定采样周期。
- 输入与输出通道、中文名称、单位及标定倍率。
- 数据类型、有效范围和可选帧序号。

例如设备开发者可采用逐行输出 `time_s,input_v,output_rad_s` 的简单文本格式。这个格式是建议的适配约定，不能假定现有设备已支持。

采样周期以设备时间戳或可信设备配置为准。电脑收到串口/网络包的间隔可能受缓冲影响，不能直接当作物理采样周期。协议自动发现只用于已知模板识别，不能承诺识别任意二进制报文和信号含义。

## 6. 自动化与异常提示

- 接收正常后直接进入现有自动建模流程：收集初始 400 点 → 自动选阶/延迟 → 在线更新。是否可更改初始点数由后续实测决定。
- 激励不足时显示“输入变化不足，正在继续收集数据”，继续按当前有界窗口策略重试，不能编造可用模型。
- 无数据时显示“设备已连接，暂未收到采样，请检查设备是否开始发送”。
- 端口被占用时显示“设备被其他软件占用，请关闭该设备的串口调试工具后重试”。
- 数据格式不符时展示少量接收预览并提示检查设备模板，不能默默把错误字段当成采样数据。
- 设备断开、时间重置、文件被截断或队列溢出时停止当前辨识段，保留已接收数据并说明原因。恢复后创建新实验段，避免把不连续数据拼成等间隔 ARX 序列。
- “停止并保存”保存采样 CSV、模型 JSON 和结果说明。在线预测误差应注明其含义，不能自动标为独立验证精度。

采集、估计、界面刷新应解耦，使用有界队列。原始数据增量写入本地记录，界面只显示有限窗口；不能依赖现有 2,000 点绘图缓冲保存完整实验。

## 7. 最小可验收版本

- 不导入历史 CSV、不复制会话 ID、不启动脚本，即可接收支持协议的真实设备数据。
- 插入设备后能在列表中看到设备；应用模板后可预览输入、输出及采样信息。
- 点击一次开始即可完成样本接收、自动定阶、在线参数更新及模型曲线显示。
- 用户能看到明确的采集/定阶进度；不需要理解 ARX、RLS 或候选阶次。
- 可停止并保存当前采集与模型；接收故障不会伪装成正常采样。
- 使用已知报文的模拟数据源验证拆包、粘包、部分行、乱码、断连、缓冲上限及序号/时间检查，再用实际设备完成端到端验证。

后续真实硬件联调需要确认实际采集设备及真实报文/列定义。模板可由界面保存；当前适配不依赖用户编写脚本，但仍需要设备输出符合受支持协议。
