# 二进制与可编程解码（0.6.0）

每个完整数据帧生成一行数值采样。预览后仍需核对输入、输出和采样周期，再开始建模。可解码 2～128 个字段，当前在线辨识从中选择一路输入和一路输出；多字段接收不等于在线 MIMO 辨识。

## 最快接入两个 double

选择 USB 串口，核对波特率等参数，数据格式选择“二进制 · 选择数值类型”，类型选 double / float64。若设备按输入、输出顺序发送两个 IEEE 754 binary64，通道填写 `input1,output1`，载荷自动为 16 字节。按设备实际格式选小端或大端。不要把串口数据位改为 64，串口仍按 8 位字节传输。

两种字节序下 `(1.0,2.0)` 的数据：

```text
小端：00 00 00 00 00 00 F0 3F 00 00 00 00 00 00 00 40
大端：3F F0 00 00 00 00 00 00 40 00 00 00 00 00 00 00
```

预设支持 float64/double、float32/float、uint8/int8、uint16/int16、uint32/int32、uint64/int64。整数使用二进制补码有符号表示，不自动缩放。带时间戳时按实际顺序增加时间列；没有时间列时填写设备真实固定周期，不能用电脑接收间隔代替。

## 帧结构

每帧 = 可选帧头 + 固定长度载荷 + 可选帧尾。帧头/帧尾使用十六进制，如 `AA 55`、`0D 0A`，各最多 32 字节。载荷不包含帧头/帧尾，自定义载荷最多 4096 字节。帧头只用于初始定位，允许跳过最多 64 KiB 前导字节，且显示跳过数量；定位后帧头、帧尾或校验错误会停止实验，防止静默丢帧污染辨识时间轴。

纯定长帧必须从完整帧起点接入。无帧头时先连接软件，再启动发送。只有固定帧尾不能保证从任意中间位置恢复同步。若发送端结构体存在内存对齐填充，应使用自定义偏移，不能假定字段紧密排列。本版不支持可变长度帧、SLIP/COBS 转义或任意厂商协议的自动识别。

接收缓冲与串口读取边界无关，可处理半帧和多帧粘连。二进制中的 `0A`、`0D` 是普通载荷字节，不会被当作文本换行。停止时未完整的帧不进入采样；剩余字节数记录在元数据中。

## 表达式解码

选择“二进制 · 可编程解码”，填写载荷字节数。解码表达式类似 Python 数值表达式，但不是任意 Python 程序；没有循环、导入、属性访问、文件或网络调用。每行赋值生成一个输出通道，允许引用前面已定义的通道。通道名使用英文字母开头的字母、数字、下划线，不得重复或与函数同名。每帧独立计算，不跨帧保存变量。

下例为 10 字节紧密排列载荷，毫秒 uint32 + float32 输入 + int16 输出：

```python
time_s = u32(0) * 0.001
input1 = f32(4)
output1 = i16(8) * 0.01
```

读取函数都以载荷第 0 字节为偏移原点，共用所选字节序：

| 函数 | 读取内容 |
| --- | --- |
| `f64(offset)` / `f32(offset)` | IEEE 754 双精度 / 单精度 |
| `u8/i8(offset)` | 无符号 / 有符号 8 位整数 |
| `u16/i16(offset)` | 无符号 / 有符号 16 位整数 |
| `u32/i32(offset)` | 无符号 / 有符号 32 位整数 |
| `u64/i64(offset)` | 无符号 / 有符号 64 位整数 |
| `bits(start, count)` | 位字段，count 为 1～64 |
| `sum8(offset, length)` | 指定字节区间求和并取低 8 位 |
| `xor8(offset, length)` | 指定字节区间逐字节异或 |
| `abs(x)`、`min(a,b)`、`max(a,b)` | 绝对值、较小值、较大值 |

支持 `+ - * / // % & | ^ << >> ~`、数值比较、`and/or/not` 和 `a if condition else b`。可使用 `assert condition` 检查帧校验值/状态；失败则停止，已接受的前缀样本照常保存。例如两个 uint8 后附一个和校验字节，载荷长度 3：

```python
assert sum8(0, 2) == u8(2)
input1 = u8(0)
output1 = u8(1)
```

真正打包的 uint6 不等于 uint16。下面两个 6 位数连续存放在 2 字节低 12 位中，剩余高 4 位不用：

```python
input1 = bits(0, 6)
output1 = bits(6, 6)
```

`bits` 固定按“第 0 字节最低位是第 0 位”编号，跨字节时低位优先组合，独立于多字节数值的大小端设置。字节 `91 0A` 解码为 17、42。其他位顺序可以用 `u8`、移位和掩码组合。

估计器使用 float64。大于 `2**53` 的整数输出会被拒绝，避免悄悄丢失计数/时间戳精度。可在同一表达式内先减去整数基准，再缩放，如 `time_s = (u64(0) - 9007199254740992) / 1000000`。表达式中间整数保持整数运算；浮点计算和最终输出仍受 float64 精度限制。

单程序最多 16,384 字符、1,024 个 AST 节点、24 层表达式嵌套、128 个通道；位移最多 64，整数中间值最多 256 位。范围校验在编译/逐帧读取时完成。解析工作与帧字节数、表达式节点数成正比（sum8/xor8 另按校验区间计），不阻塞模型线程，但不声明硬实时能力。

## 试解码、诊断与模板

“试解码”调用与真实串口相同的解码器，接受最多 8192 字节的十六进制数据，预览前 120 行，返回所有已解码帧数、剩余字节、前导跳过字节和错误。部分正确帧后出现错误时，正确前缀仍可查看。界面内置五种完整示例，可复制其结构再修改。

真实连接后的“二进制接收诊断”显示最近 96 字节、累计字节数、帧数和等待拼接数量。`metadata.json` 保存完整解码配置和最后的诊断、剩余帧字节数；`raw_samples.csv` 保存解码后数值而不是完整线缆字节抓包。设备模板记住类型、字段、帧头/尾、字节序及表达式，刷新运行中的连接也会恢复显示。

试解码 API：

```json
{
  "decoder": {
    "mode": "preset", "dtype": "float64", "byte_order": "little",
    "columns": ["input1", "output1"], "header_hex": "", "trailer_hex": ""
  },
  "hex": "00 00 00 00 00 00 F0 3F 00 00 00 00 00 00 00 40"
}
```

POST `/api/acquisition/decode-preview`。连接 API `/api/acquisition/connect` 在原串口参数外增加 `format: "binary"` 和同一份 `decoder` 对象。自定义使用 `mode: "custom"`、`payload_bytes`、`code`。旧请求不提供 format 时保持 CSV；CSV 文件跟随与原有导入、回放流程不变。
